## Method reading

V3 qualifies verifier actions, then chooses verifier subsets by replaying a FIXED proposal's transactions. It does not itself re-generate the Adaptive BARD proposal with different proposal-expert subsets. Thus it can block a harmful proposed edit, but does not directly learn which generative expert caused the edit. Distinguish verifier-portfolio interaction from proposal-expert ablation.

The source splitter unions patient/group and image SHA. Downstream portfolio/canary guards compare recorded group IDs; they do not independently re-hash all images. Preserve splitter lineage and input hashes; do not claim those downstream calls alone catch identical images carrying different group IDs.

Operational fixes: exact per-case proposer maps, explicit skip for insufficient controls, PLIP native77-token rejection instead of runtime shape crash. Flattened config uses disabled probe64 and unifies BiomedCLIP interface fault groups. No threshold relaxation or target selection.
