# Cross-modal correspondence development pilot

Identity `medsg-correspondence-dev-v1`. Frozen before looking at target boxes or running models. Existing Task7 from MedSG-Bench (NeurIPS2025 Datasets and Benchmarks) is reused, not proposed as new data.

Vector: Does reference-derived anatomical relational context improve target localization over direct joint vision, a simple entity-name bridge, and geometry copying across different modalities?

- Task7 public release revision `4fa0c0dafed69b50d8e928ac52d63de5d2481ab8`; 2000 questions. Local JSON and ZIP are frozen sources. These are normally benchmark cases; this explicitly declared subset is DEVELOPMENT and will not later be presented as a pristine held-out test.
- Select up to four cases each for seven transitions: aligned same-case BraTS MRI→MRI control, CT→MRI, MRI→CT, US→MRI, MRI→US, CT→X-ray, X-ray→CT. For primary nonaligned cases require two images. Hash-sort metadata index+image references; deduplicate every dataset/case identifier across selected source and target. No selection by target box, answer, organ label, similarity or performance. Patient IDs are filename-derived, not independently verified.
- Only source and requested target are used. For BraTS controls this omits other unrequested contrasts and is explicitly a two-image task adaptation, not official full-sequence reproduction. Preserve official source/target intent, anonymize all paths, never send anatomy-bearing filenames or target boxes to inference.
- Source observer: fixed Qwen2.5-VL-7B-Instruct, only reference image with benchmark's red box. Predict JSON entity name, visible appearance, and anatomical relations to landmarks. At most six relations, 384 new tokens; no label-guided repair. Same frozen model acts as target grounder in independent calls. No new expertise, training or gate.
- Grounding arms: joint source+target; target only with no reference identity (negative control); target+predicted entity name; target+entity and anatomical relations; target+entity/relations/appearance; target+the next selected case's full predicted description (deliberately wrong reference control). Invalid source parses have no bridge arms and coverage is reported.
- Geometry baseline: detect source red pixels using fixed R>200,G<80,B<80 with at least16 pixels, enclose them, scale coordinates by target/source dimensions. Never tune thresholds to gold. Count red pixels on targets and report possible preexisting markup. This legitimate input-cue baseline can solve aligned examples and must precede any semantic claim.
- All learned arms return JSON [x1,y1,x2,y2] in original TARGET PIXEL coordinates. Prompt states target dimensions. Strict numeric parser checks ordering and bounds; no model-specific guessed coordinate rescaling. Invalid output is a failed localization.
- Metrics: target IoU, mean IoU including invalid=0, accuracy IoU>=0.5, parse coverage, per-transition results, matched bridge/direct differences; geometry performance separated for aligned versus nonaligned. Gold target boxes loaded only in offline evaluation.
- H1: reference relations help the frozen target localizer consistently beyond both name and direct image baselines in nonaligned transitions. H0: geometry, entity identity, appearance, prompt format, or lack of perception explains all effects. A relation bridge advantage is only a baseline finding; explicit graph algorithm innovation requires additional discriminating experiments.
- Stop representation expansion if entity name alone matches relation context, geometry accounts for results, wrong reference has no measurable effect, or target localization has no usable headroom. If reference-specific relational benefit survives, inspect grounding validity and compare lossless relation table/strong established methods before claiming novelty.
- Same device mapping as prior runs; respect other active processes. Cost includes source description calls and target grounding. No full-modality, full-anatomy or unseen-pretraining claim.

## Pre-evaluation engineering amendment: v2

v1 canary produced zero valid boxes in 6 calls because native bbox_2d object output disagreed with the requested numeric array, one output truncated at 48 tokens, and coordinates could refer to the processor-resized image. No gold scores were read. Preserve v1 records; do not interpret as model/task failure.

v2 repeats the identical metadata-selected 28 cases, all source observations and all target calls under a new identity. Explicit aspect-preserving smart_resize to multiples of28 within the same processor pixel budget makes input and model coordinates agree; invert the known image transform to original target coordinates for scoring. Prompt native single-object bbox_2d JSON with128 outputtokens. Parser accepts one bbox_2d object or a four-number list and rejects out-of-bounds boxes without clamping. This is an engineering correction, not a research contribution. All scientific hypotheses and evaluation rules above remain frozen.

## Target-specialist replication (frozen before v2 scores)

`medsg-correspondence-specialist-dev-v1` repeats the exact28 development cases and same6 arms, changing ONLY the target grounding checkpoint to the benchmark authors' released MedSeq-Grounder revision7c18e944897e8fdb86e93dcf919ad78517330df4. Keep the28 Qwen source observations byte-identical, explicitly log separate observer/grounder identities. This tests whether any apparent relation effect is specific to weak generic localization. It also establishes a task-specialized tool baseline consistent with the fixed-tool substrate scope; it is not our trained method or independent evidence on unseen data. MedSeq-Grounder was trained on MedSG-188K; exact training/exposure overlap requires a later audit before any generalization claim. Use native coordinate adaptation and same strict validation as v2. Do not pool scores across checkpoints. Comparison remains development-level and does not certify method novelty.
