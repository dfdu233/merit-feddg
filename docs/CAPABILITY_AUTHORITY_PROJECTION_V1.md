# Capability-bounded free-text projection v1

## Research vector

This branch isolates one question only:

> When a frozen specialist has a native decision about one medical attribute, can
> the generalist use that decision without allowing the specialist to rewrite
> unrelated parts of a free-text answer?

The experiment is intentionally based on the fixed 12-case XRV TRAIN pilot from
`350c313`. That pilot exposed examples in which a very low XRV positive score was
serialized as text and the LLaVA-Med answer moved in the opposite semantic
direction. This branch does **not** add segmentation, retrieval, Agent planning,
new uncertainty signals, a verifier, or training.

The output remains complete free text. The method does not reduce evaluation to a
Yes/No answer.

## Bit flip

The prior collaboration interface mainly controls **how strongly** an evidence
conditioned language distribution is used. Here the specialist instead receives a
narrow semantic authority: it may change only the marginal over the one native
binary variable it actually predicts. Preferences among full-text answers that
express the same value of that variable are inherited from the frozen generalist.

This is a research hypothesis, not a novelty claim. Minimum-KL projection and
posterior constraints are classical. The experiment asks whether using that idea
as a capability boundary addresses a concrete failure of frozen medical
specialist/generalist collaboration.

## Free-text finite-pool projection

For one question, reuse a fixed pool of complete answer texts already generated by
the previous pilot. Let the frozen generalist assign a length-normalized sequence
score `s_i` to each candidate and normalize over this finite pool:

\[
p_i = \frac{\exp(s_i)}{\sum_j\exp(s_j)}.
\]

A conservative, task-specific mapper assigns each complete text to one of:

- positive for the question-matched finding;
- negative for that finding;
- unknown/unmapped.

The XRV raw sigmoid is **not** treated as a calibrated probability. For this pilot
only, it is mapped through TorchXRayVision's published operating-point
normalization, which places the source model's own operating point at 0.5. Call
that source-native decision coordinate `r`.

The projected candidate distribution solves the finite-pool minimum-KL problem
whose constraints are:

1. the total unknown/unmapped mass is unchanged;
2. among mapped candidates, positive mass is `r` and negative mass is `1-r`.

The closed-form solution rescales groups and preserves all within-group odds:

\[
q_i = p_i\frac{m_g^*}{m_g}, \quad i\in g.
\]

Thus, if two free-text answers encode the same specialist-native finding value,
the specialist cannot change their relative preference. Their wording, additional
findings and explanation remain controlled by the base model's finite-pool score.

If the candidate pool lacks either a positive or a negative complete text, the
projection is declared infeasible and falls back to the base pool selection. The
method never invents a missing counterfactual answer merely to make the projection
look successful.

## Candidate pool and controls

The pool is the deduplicated set of full texts already produced in `350c313` by:

- incumbent;
- focused XRV text;
- fixed blend;
- fixed CAD;
- ACD;
- source-only uncertainty weighting;
- source-ACD.

These are proposal sources only. The new projection does not assume any proposal
is correct. Every candidate is rescored as a complete sequence under both:

- the base context without the newly added XRV packet;
- the focused text context with that packet.

This yields three distinct comparisons while keeping output free-form:

- `base_rerank`: finite-pool base sequence preference;
- `text_rerank`: the same pool scored after language transport of XRV evidence;
- `authority_projection`: base preference after the native capability constraint.

The transport diagnostic asks whether the language-conditioned distribution moves
the positive/negative pool marginal toward or away from the source-native decision
coordinate. It does not call either model medically correct.

## What a positive result would mean

A useful first result would be evidence that:

1. language transport sometimes moves the free-text semantic marginal opposite
   to the XRV-native direction;
2. the authority projection removes that direction inversion by construction;
3. full-text answer quality or harm/rescue behavior improves relative to both the
   incumbent and simple finite-pool reranking;
4. the effect is not explained merely by candidate availability.

This would support continuing the vector. It would **not** yet establish a general
plug-and-play Agent, a calibrated expert fusion rule, or an ICLR-level contribution.

## What a negative result would mean

- If both semantic sides are usually absent from the pool, candidate acquisition
  rather than projection is the next vector.
- If both sides exist but the projection does not help, the language transport
  failure is probably not the dominant bottleneck.
- If the specialist-native direction itself is often wrong, the next vector is
  source reliability/domain shift, not a more complicated projection.

## Running

Generation uses no references:

```bash
python scripts/run_authority_projection_train.py \
  --source-run runs/uncertainty-train-v1 \
  --output runs/authority-projection-train-v1 \
  --gpu-uuid <authorized-visible-GPU-UUID>
```

A small scheduling canary can be run with `--max-cases 1` in a fresh output
directory. Evaluation is a separate offline step:

```bash
python scripts/evaluate_authority_projection_train.py \
  --run runs/authority-projection-train-v1 \
  --anchor-root /home/dbw/ANCHOR
```

Do not tune the source coordinate, candidate pool, semantic mapper or selection
rules from evaluation references. This first experiment should remain a mechanism
probe on TRAIN.
