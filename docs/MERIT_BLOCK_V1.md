# MERIT-Block v1 — Counterfactual Semantic-Block Intervention

## Research question

MERIT-Block studies one narrow question:

When should a specialist-induced continuation be admitted into a frozen
Generalist's autoregressive trajectory?

The method does not claim to determine whether a specialist is medically
correct. It tests whether a competing expert-induced continuation is
specifically supported by the current patient's expert context rather than by a
generic contextual-entrainment effect, and it limits the duration of that
intervention.

## Motivating failure: Expert-Induced Trajectory Drift

A transient expert observation can change an early generated token or phrase.
Autoregressive conditioning then makes that intervention part of every
subsequent state, so a local error can become a long downstream trajectory
shift.

MERIT-Block separates four operations:

1. proposal: Generalist and expert branches propose from the exact same prefix;
2. verification: real expert context must prefer its block over the Generalist
   block, and this preference must exceed wrong-patient expert controls;
3. commit: one complete block is written atomically;
4. locality: expert context is discarded after the commit; only token IDs
   survive into the next generation state.

Persistent expert context is an ablation, not the primary method.

## Same-prefix competing blocks

At committed prefix p,

    B0 ~ G(I, q, p)

and for expert e,

    Be ~ G(I, q, p, Ee).

Both start from the exact same token prefix. No decoded answer is re-tokenized.

For open-ended generation a block can be a fixed token span or the first
sentence prefix of a longer proposal. CE, OE and report generation therefore
use the same decoder; only the total output budget differs.

## Paired block preference

For a context C, define the length-normalized paired sequence preference

    ell(B | C) = mean_t log P(B_t | p, B_<t, C).

The default uses mean transition log probability because expert and Generalist
blocks can have different lengths in OE/report generation. Sum log probability
is retained as an explicit ablation. We do not call the mean score a sequence
log-odds ratio.

For real expert evidence,

    m_real^e = ell(Be | Ee) - ell(B0 | Ee).

For K wrong-patient expert controls,

    m_k^e = ell(Be | E_tilde_e^k) - ell(B0 | E_tilde_e^k).

Counterfactual specificity is

    Gamma_e = m_real^e - median_k m_k^e.

The primary admission rule is

    Accept(e) iff m_real^e > 0 AND Gamma_e > 0.

Absolute Support requires the real expert branch itself to prefer Be.

Counterfactual Specificity requires that this preference exceed the typical
preference induced by wrong-patient expert context.

This fixes the known Gamma-only logical failure:

    m_real = -0.1
    median(m_control) = -2.0
    Gamma = +1.9

where Gamma is positive even though the real branch still prefers B0.
Gamma-only, real-only and conjunction are frozen ablations.

Among several admitted experts, v1 chooses the largest Gamma. Because a maximum
over more experts can induce a winner's-curse effect, 1 / 2 / all-expert
experiments are mandatory; multi-expert superiority is not assumed.

## Atomic, ephemeral commit

If no expert is admitted, commit B0.

If expert e* is admitted, commit the complete Be* token block. In the primary
ephemeral policy, the next incumbent proposal is again generated by the
evidence-free Generalist from

    p' = p + Be*.

The persistent arm keeps the last accepted expert context and is used only to
measure trajectory contamination.

## Matched controls

Controls contain expert evidence from another patient/study, while the receiver
still sees the current image, current question and the same candidate blocks.

The control builder:

- rejects answer/reference/label fields;
- requires a different patient/study group_id;
- matches answer-blind metadata, by default modality and task;
- keeps expert identity fixed;
- deterministically creates matched and random wrong-patient controls;
- creates a deterministic shuffled-expert fixture.

No target image is substituted when controls are insufficient. The conjunction
arm then abstains.

## Trajectory-drift diagnostic

After an accepted block, an optional diagnostic compares

    G(I,q,p')

with

    G(I,q,p',Ee)

at the same forced prefix for several subsequent steps. At each step the
Generalist greedy token is appended to both probes, so free-generation
divergence cannot confound residual context influence.

The diagnostic reports Jensen-Shannon divergence and greedy-token disagreement.
It is not a correctness metric.

## Frozen primary protocol

configs/merit_block.yaml defines the primary method:

- fixed 8-token blocks;
- ephemeral expert context;
- matched wrong-patient controls;
- K=3 controls;
- conjunction admission;
- length-normalized mean transition log probability;
- all available experts;
- 64-token VQA budget and 256-token report budget.

Ablation scores must never be used to replace the primary method after target
labels are observed.

## Required one-factor ablations

### A. Intervention granularity

- 1 token
- 4 tokens
- 8 tokens, primary
- 16 tokens
- sentence block

Question: does intervention granularity determine how much a transient expert
perturbation propagates into later autoregressive states?

### B. Intervention locality

- ephemeral, primary
- persistent expert context

Report downstream same-prefix JSD and harmful/corrective outcomes separately.
This directly tests Expert-Induced Trajectory Drift.

### C. Counterfactual design

- no control / real-only
- random wrong-patient control
- matched wrong-patient control, primary

Question: is the observed preference patient-specific or a generic medical
context effect?

### D. Admission logic

- Gamma > 0 only
- m_real > 0 only
- m_real > 0 AND Gamma > 0, primary

This directly tests the mathematical error identified in the previous design.

### E. Number of controls

- K=1
- K=3
- K=5

This tests score stability rather than choosing K on target accuracy.

### F. Variable-length OE score

- mean transition log probability, primary
- sum transition log probability

Report performance stratified by Generalist/expert block-length difference.

### G. Expert count

- one expert
- two experts
- all experts

Report acceptance and harmful/corrective outcomes. This diagnoses winner's
curse and correlated specialists.

### H. Evidence condition

The mechanism study must explicitly test:

- native real expert evidence;
- plausible-but-wrong expert evidence;
- irrelevant expert evidence;
- shuffled expert output.

Shuffled evidence is generated label-free by the control builder.
Plausible-wrong and irrelevant evidence should be constructed only on a
designated mechanism/source cohort where correctness/applicability can be
audited; they must not be selected from target results.

The key diagnostic rates are:

    P(accept | E+)
    P(accept | E-)
    P(accept | E_irr)

If MERIT rejects irrelevant evidence but frequently accepts plausible wrong
evidence, the paper must state that counterfactual specificity does not solve
specialist correctness.

## Tasks

The same algorithm is evaluated on:

- CE VQA;
- OE VQA;
- report generation.

Report generation is not converted into a different claim-gating pipeline.
Clinical claim/RadGraph metrics can be used for evaluation, not for a separate
inference algorithm.

## Main scientific hypotheses

The ICLR story should stand or fall on three empirical findings:

1. Token-level or persistent expert injection causes measurable downstream
   trajectory contamination after a local expert intervention.
2. Matched wrong-patient controls separate patient-specific contextual
   influence from generic context entrainment better than no/random controls.
3. Blockwise ephemeral admission lowers harmful expert intervention while
   retaining useful corrections across multiple receivers, specialists and
   CE/OE/report tasks.

None of these is asserted by construction.

## Positioning

MERIT-Block should not claim that counterfactual context comparison, PMI-like
scores, block verification, or training-free medical hallucination mitigation
are individually new.

The defendable combination-level distinction is:

Existing expert-augmented VLMs commonly expose specialist outputs as persistent
context or fuse expert influence token by token. MERIT instead forms competing
semantic continuations from the same autoregressive state, evaluates their
paired preference under real and matched counterfactual specialist evidence,
atomically admits one local block, and then discards expert context.

Use the term Ephemeral Expert Intervention or Temporary Contextual Revision.
Do not call the method model editing because model parameters never change.

## Execution

Freeze the ablation plan before benchmark scoring:

    python scripts/build_merit_block_ablation_plan.py \
      --config configs/merit_block.yaml \
      --output runs/merit-block-ablation-plan.json

Build controls from frozen real EvidenceItem packets:

    python scripts/build_merit_block_controls.py \
      --input runs/real-evidence.jsonl \
      --output runs/block-evidence-controls.jsonl \
      --count 5

Run a primary arm:

    python scripts/run_merit_block.py \
      --manifest /path/to/label-free-manifest.jsonl \
      --evidence-packets runs/block-evidence-controls.jsonl \
      --receiver-config /path/to/receiver.yaml \
      --arm full \
      --output runs/merit-block-full.jsonl

For the trajectory-drift experiment, add:

    --drift-horizon 16

Summarize without references:

    python scripts/summarize_merit_block_runs.py \
      --run full=runs/merit-block-full.jsonl \
      --run persistent=runs/merit-block-persistent.jsonl \
      --output runs/merit-block-mechanism-summary.json

Benchmark references are joined only afterwards by the frozen evaluator.
