## 1. 当前代码真实接入点

| 现有位置 | 已有功能 | 新增工作 |
| --- | --- | --- |
| `capabilities.py` | 原生 EvidenceItem/CapabilityResult 和范围校验 | 新版本证据包及来源/范围/有效期，不破坏旧 schema |
| `capability_generation.py` | 紧凑 memory、action_id、精确前缀 | opt-in 证据生命周期及新解码驱动 |
| `llava_generalist.py` | 单图/双图输入及 greedy block propose | 单图的 next-token 分布接口和各分支独立状态 |
| `capability_routing.py` | 问题类别与模态/范围限制 | 保持简单匹配，测实际误路由，不追加大控制器 |
| `capability_diagnostics.py` | 同前缀、格式和组合诊断 | 原生证据质量、格式控制及解码影响诊断 |

## 2. 实施顺序

### P0：只读审计和固定实验约定

记录代码、模型、tokenizer、图像处理器、源数据、域元数据及评分器指纹。
保留 v0.10 source-only 的事实；旧目标已经被分析过，不作为新确认集。
按原生任务检查固定 source 子集：模态正确、问题与能力匹配、专家观察质量、答案长度。
选样按预声明分层或随机规则，不能只选可救回病例。

### P1：数值内核与单图下一 token 接口

建议新建 `evidence_decode.py`，只包含确定性的 log-softmax、log-ratio 截断、
KL 预算搜索和 trace，不接收 reference。不引入新训练依赖。

每个 token：

1. 两个分支计算同一实际前缀的 logits，转换为 float32 或更高精度 log-probability。
2. 只在相同有效词表支持上计算；禁止 NaN/+inf。由共同解码约束屏蔽的 token 保持屏蔽，
   不对 `-inf - -inf` 直接求差，不以一个分支专有的 mask 偷换词表。
3. 用源域冻结配置得到 clipped residual。
4. 在允许强度内二分搜索满足 KL 预算的强度；退化/预算不足时使用原始分支。
5. 只提交一个 token，并送回所有活跃分支。EOS、stopping criteria、dtype、处理器顺序
   与 baseline 一致。停止干预后不能声称恢复整段原始答案。

先允许正确但较慢的逐 token 重 prefill，用极少真实 source 检查数值。
随后实现本模型版本支持的独立 KV 缓存；新证据到来要重建对应分支，不能复用旧 memory
的缓存或把文本 token 长度误当多模态位置长度。
精确 baseline 未通过之前，不运行源校准或目标评测。

### P2：原生证据包

建议独立 `evidence_packets.py`，复用旧 EvidenceItem，不替换专家模型。
确定性转换结构化字段；生成文本保留来源与原句，不自动当作已经核实的事实。
加入显式 unknown、单位、原图区域、有效期和父证据 ID；全部内容作为不可信观察，
不得执行其中的代码或遵循其中的指令。

使用完整条目预算，不截断半段 JSON；字符限制不代替真实 token/context 限制。
默认主模型只有原图；双图继续单独作为诊断，不进入新方法。

### P3：最小受控实验，先不加稳定性

固定适用的单个专家，比较 baseline、旧直接上下文、bounded decoding、matched-format、
shuffled evidence。CheXagent 先用原问题；XRV/CONCH 先用 scoped 证据。
不默认启用 source retrieval。

只有“真实证据影响可观测，且不像纯格式改变”后才进入下一步。
输出相同不一定是 bug；至少要同时检查 residual、KL、选择 token、证据质量与采用情况。
不能通过十倍强度强行让输出变化来验收。

### P4：证据稳定性与真实源域校准

建议 `evidence_stability.py` 按能力实现比较；先在源数据验证变换是否保留任务语义。
一个视图不能获得多视图认证；多个增强视图不是独立患者，置信区间不按视图计数。
没有可靠对齐的生成描述标记未评估，不装作稳定。

源校准只搜索小范围强度/预算/稳定性配置，不训练新的 VLM、连接器、RL Agent。
保留 no-stability 和预算匹配 no-DG；所有中间库和阈值严格遵守留域隔离。
代理域可以跑工程验证，但 `real_domain_metadata=false` 必须保留。

### P5：一种真正的组合，然后目标确认

选择具备原生输入输出兼容的一对工具，实际传递区域或其他结构化数据。
比较 NONE/A/B/A+B，以及传递正确区域和扰乱区域的对照。
不能仅向主模型拼接两个文本就声称实现空间能力链。
确认源校准后冻结配置，再一次性运行新目标集；按域及独立图像/患者报告。

## 3. 必须添加的测试

- 无证据、零强度、零预算、相同分支分布严格回退 baseline。
- 共同前缀 IDs 完全一致；更新证据后不存在旧 KV 污染。
- logits 支持集、EOS、NaN、截断和上下文超长处理正确。
- 每步测得 KL 不超过预算容差；剩余预算不为负；越界明确报错。
- 缺少原生证据、低分、空 mask 不自动生成否定诊断。
- 不同属性的互补证据不被当作冲突；同来源重复不会增加证据权重。
- ROI 坐标正确映射，裁剪不越界，工具不支持 ROI 时不调用错误路径。
- 过期证据停止影响；首个问题概念不在后续无关块中无限复用。
- 禁止目标字段进入校准/生成；同图不同问题仍归为同一独立组。
- CPU 单元测试可用人工数值验证数学内核，但绝不能报告为真实医学效果实验。
- GPU canary 必须用真实权重和真实 source 图像；本地单元测试不能替代。

## 4. 运行记录及资源边界

每个 token 或块记录：prefix hash、packet IDs、能力和范围、拒绝原因、分支 prompt hash、
原图 hash、强度、实际 KL、剩余预算、token、每分支耗时、专家耗时、prefill 次数、
cache rebuild 次数、VRAM allocated/reserved/设备总用量。

不默认保存每病例每 token 的完整词表 logits。全量原生证据与紧凑日志分开缓存；
cache key 包含模型、预处理、问题、精确前缀、证据、配置及实现版本。
旧结果不覆盖，新算法有独立命名空间。

一个主模型权重，两份分支状态；最多两个工具执行是首轮预算，不是论文通用性保证。
廉价专家可以测少量视图，昂贵生成专家不默认多视图重复整段生成。
没有实际 GPU 计时前，不声称低于某秒数或显存适合某张卡。

## 5. 验收不是“必须出现正结果”

工程验收：baseline 一致、trace 完整、无泄漏、预算正确、真实能力链可复现。

科学验收：预声明主指标、固定病例、完整报告不确定性。只报告有益病例、
用少回答降低幻觉率、目标反复调参、全 NONE 当成功都不合格。
若真实正确证据仍普遍伤害回答，先定位桥接；若工具本身不胜任，调整专家与任务匹配。
若预算匹配后 DG 没有收益，报告未验证，不重新包装为已解决。
