## Bit Flip status

Unchanged and unproven. A bug fix is not a new Bit Flip. Question-first parsing is
also not inherently novel. The testable hypothesis here is narrowly operational:
showing a parser the expert's finite catalog may cause it to omit requested but
unsupported entities; extracting the requested variables before catalog linking
might reduce that error. This is a hypothesis, NOT a claim that the cited papers
all make this mistake or that all catalog-conditioned parsing is inferior.

## One Vector

Can a frozen model recover requested entity-attribute pairs and relation operands
from natural questions WITHOUT silently deleting unsupported concepts, at useful
coverage compared with the unchanged regex and catalog-conditioned baselines?

## Core / periphery

Core: request interpretation, reviewed native aliases, the unchanged de056a8
admission filter, and independent answer-blind semantic review.
Periphery frozen: answer decoding, candidate construction/projection, expert
models and weights, RAG, uncertainty, verifiers, planners and clinical scoring.
No original runtime/configuration/score/protocol is modified. No actual answer
is generated by the new runner. Its only generated text is private parser JSON.

## Minimum discriminating experiment

- Prepare a deterministic subset of up to 100 CXR TRAIN questions by SHA256 with
  seed 197. All official splits remain unchanged; this is a diagnostic subset,
  NOT overall accuracy. Default is 12 for an interface pilot.
- Fixed: question, language backbone, JSON format, instructions, decoder and token
  budget. The sole prompt ablation is expert-catalog exposure.
- `question_first`: one question-only parse, reused for both experts.
- `catalog_conditioned`: same instructions with each expert's native catalog.
- `old_regex`: record the unchanged existing decision separately. It does not emit
  the same atomic representation, so do not fabricate comparable atom F1 for it.
- Neither parser receives images, predictions, expert scores, references or gold
  request annotations. No retries/repair loops. Invalid/truncated outputs count.
- Every atom has copied entity/cue spans. Unknown entities remain literal strings;
  ambiguous aliases fail rather than being mapped to the first matching label.
- Both relation operands and order are retained. The old delivery filter has no
  relation operator: relation requests do not become flat global permission.
- JSON validity/copied spans DO NOT prove that all required atoms were extracted.
  `complete=True` in the study bridge is explicitly model-asserted, not certified.
  Do not enable production enforce from this parser until independent evaluation.

Independent reviewer(s) fill `review-template.jsonl` before seeing predictions.
They label question requirements, not patient diagnoses. Review all frozen cases,
including unknowns and failures; the evaluator refuses incomplete review sets.
Use a second blinded reviewer/adjudication for disputed requests where available.
No clinical reference is needed. No reviewed labels are used to train or tune.

Primary metrics: exact requirement-set agreement, atom/relation precision and
recall, missing/extra atoms, syntax failure, unknown coverage, retained relations.
Unknown is not scored as success for a fully interpretable gold question.
These are request-level metrics, not clinical accuracy or OOD reliability.

Optional private native packets allow an OFFLINE delivery comparison:
`id`, exact `question`, `study_identity`, `image_sha256`, `items` (EvidenceItem JSON).
Identity/image binding is required. Origin is trusted/verified by the caller,
not cryptographically proven. The parser never sees these packets. Re-evaluate
both predicted and independently reviewed requests through the SAME unchanged
filter. Report unexpected/missed admission RELATIVE TO THAT POLICY. This is not
an independent definition of medical usefulness. Missing packets are unmeasured,
not correct rejection. Use all selected cases for parser metrics regardless.

## Stop and re-vector rules

1. Syntax failures dominate: report them; consider existing GCD as an interface
   baseline, not a new algorithm. Do not quietly retry or tune on the audit set.
2. Omission/mislinking persists: automatic semantics remains the bottleneck;
   do not start reliability or claim that stricter rejection is a solution.
3. Both methods match human structures similarly: keep the simpler method;
   stop claiming an advantage for catalog separation.
4. Interpretation works but same-policy delivery differs: inspect the compiler /
   mapping. A relation cannot be authorized by merely seeing one operand.
5. Interpretation and actual-packet delivery agree with review: only then test
   useful correction vs harm, with fixed candidates/budgets and strong baselines.

Velocity: one reviewed result distinguishing semantic omissions, syntax problems,
native-linking errors and actual-payload failures; not another large benchmark.

## Remaining scientific limitations

This is a diagnostic baseline, not the paper's core novelty. It does not solve
specialist correctness, automatic ontology alignment, image-dependent references,
clinical reasoning, or free-text locality. The atoms represent required variables;
this schema is not a complete logical form for AND/OR, negation or quantified
medical statements. Cues are retained for review; no logical entailment guarantee.
Within-group posterior invariance (earlier work) is not general invariance of all
other medical marginals. Admitted text can still influence non-target claims.
